# Skill index (clinozy-be)

Master directory of all project skills. **Consult this skill first** to determine which skill(s) to invoke based on what you just changed or are about to change.

For **Cursor-built-in** skills (`~/.cursor/skills-cursor/`), see **be-cursor-global-skills**.

## I want to… (decision tree)

Start here — map your intent to the skill or **chain** to run (chains are named sequences in
`agent-os/skills/chains.json`; run them with `pnpm agent-os:plan-skills <file>` or the matching
`/be-route-complete` · `/be-schema-complete` · `/be-worker-complete` · `/be-new-domain` command;
their steps, in order, are the chain rows of [`agent-os/docs/skill-triggers.md`](../../docs/skill-triggers.md)
— generated, so this index keeps no copy of them):

- **Add a whole domain / sub-domain** → **new-domain** chain
- **Add or change an API route** → **route-change** chain
- **Change a Drizzle schema / table** → **schema-change** chain
- **Add an event / queue / worker** → **worker-change** chain
- **Add / adjust seed data** → **be-seed-maintainer**
- **Add / rename / remove an env var** → **be-env-schema-add**
- **Write or reorganize `docs/**`** → **be-docs-maintainer** (audit-only pass → **be-docs-audit**)
- **Bump or add a dependency, or an agent tool pin** (`tooling/setup/agent/tool-versions.sh`) → **be-dependency-security**
- **Finish any code change (definition-of-done)** → **be-change-completeness-guard**
- **Review before merge** → **be-pre-merge-review** pipeline (`/be-pre-merge-review`: be-sql-design-reviewer, be-rls-reviewer, be-idempotency-reviewer, be-production-hardening-reviewer and be-verifier, the ones the diff needs, at once in the background; findings in `REVIEW.md` → Findings format)
- **Release / deploy to production / production readiness** → **be-path-to-production** (`/be-release`; its step 1 runs the **be-prod-readiness** pipeline, `/be-prod-readiness`)
- **Start or continue a design iteration, step by step** → **`/be-iteration`** (asks the opening questions; walks `docs/design-workflow/process/iteration-guide.md` — open, `pnpm iteration:intake`, plan, approve, kick off, close, freeze)
- **Plan a design iteration** ("plan iteration <name>") → **iteration** chain, first half: **be-iteration-planning** (no code — `KICKOFF.md` with its ROUTE ledger + `plans/`; stops after every step)
- **Implement an approved iteration** ("kickoff", "kickoff iteration <name>", "start implementing <iteration>") → **iteration** chain, second half: **be-kickoff-iteration** (one ROUTE row at a time, `AS-BUILT.md`, a review stop after every row)

Full trigger detail is in the tables below and in [`agent-os/docs/skill-triggers.md`](../../docs/skill-triggers.md).

## Routing

One map for "I changed X → run skill Y", generated — never edit a copy of it:

- **File pattern → skills:** [`agent-os/docs/skill-triggers.md`](../../docs/skill-triggers.md), generated by `pnpm agent-os:generate` from [`chains.json`](../chains.json) (the multi-skill chains, run in their order) and each skill's own `trigger` / `triggerNote` frontmatter. The edit hook reminds from the same rows (`agent-os/hooks/skill-routing.json`). To change a route, edit that frontmatter or `chains.json`, then regenerate.
- **A request or a moment → skill** ("plan iteration", "why did CI fail", "ready for production", "finishing a change"): [`be-skill-router.mdc`](../../rules/be-skill-router.mdc), always in context.
- **Several chains in one change:** new-domain → schema-change → worker-change → route-change, then be-test-generator, the doc skills (be-tsdoc-export-guard, be-overview-doc-maintainer, be-system-narrative-maintainer, be-docs-maintainer), be-structure-maintainer, and `pnpm tsdoc:check` last.
- **Not routed by file:** be-supabase-porting (manual only, `/be-supabase-porting`); be-pr-babysit, be-split-to-prs, be-ci-investigation and be-docs-audit (on request); be-cursor-global-skills (reference: Cursor's built-in skills).

| **CI**         | `pnpm ci:quality` (or individual: validate, validate:domain, routes:catalog:check, db:migrate:lint, tool:sync-env-example, deps:audit)                       | Verifies repo on PR                                                                      |

Do not run the same command in agent and again manually unless fixing a failed hook/CI step.

## New requirement workflow

When the user gives a **new requirement**, read **`docs/getting-started/requirement-intake.md`**, identify the requirement type, post a **Plan** once for **go**, then run the **Skills to run** in order for that type. The rule **be-new-requirement-intake.mdc** triggers when the intake doc is referenced.

## Maintaining this index

When a **new skill is created**, name its folder (and frontmatter `name`) with the `be-` prefix, then add it to:

1. Its own frontmatter: `trigger` (the files that call for it) and `triggerNote`, or a step in a
   chain of `agent-os/skills/chains.json` — then `pnpm agent-os:generate` (the routing map, the
   Project skills table and the rules table here are generated)
2. A row in `agent-os/rules/be-skill-router.mdc` when a request, not a file, calls for it
3. A `.mdc` auto-attach rule, if any, named `<skill>-sync.mdc` (e.g. `be-env-schema-add-sync.mdc`,
   so it inherits the `be-` prefix)
4. `CLAUDE.md` under "Keeping Docs and Skills in Sync"
5. Assign it a group in `agent-os/skills/groups.json`

Whenever a **skill's `SKILL.md` changes** (new skill or edit), run **`pnpm agent-os:lock`** to
refresh its sha256 in [`agent-os/skills-lock.json`](../../skills-lock.json), then commit the
SKILL.md and the lockfile together. `pnpm agent-os:check` recomputes each hash and fails on drift,
a skill missing from the lockfile, or a stale lock entry (provenance is enforced, not hoped for).
